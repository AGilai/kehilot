# Seating (real data) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** per-Kehila hall layouts edited by gabbaim on the web (paste from Google Sheets or draw), seat
ownership by registered families and by seat holders without an account, weekly release per prayer (member
in the app, gabbai on behalf, the old Form's responses upload), and the member/print views on real data.

**Architecture:** the server owns layouts (versioned, effective from a Shabbat), holders, assignments and
weekly states, and is the only place that cuts a member's view (his block, his rows ±2 — never the hall).
The client parses pastes and suggests matches (pure TS), the editor saves through strict routes. The seat
preview's views (SeatCard, SeatPage, SeatPrint) switch from fixtures to the API.

**Spec:** `docs/superpowers/specs/2026-10-27-seat-release-preview-design.md` (all sections, incl. the owner
notes and the CTO rulings at the end). Design: `docs/UX-DESIGN.md` §15–§16, frames P24–P30.

## Global Constraints

- Member sees only his block and his rows ±2; the API returns only that cut to a member. The whole hall and
  any names: gabbaim only. No seat numbers shown anywhere; seat ids are internal.
- Holders without an account are personal data entered by gabbaim: never in logs or pushes; deletable by a
  gabbai; removed with the Kehila; a linked holder's record is deleted after its seats move.
- Nothing is matched or linked without a gabbai's confirmation.
- Layout changes take effect from a chosen Shabbat; past Shabbatot keep their state.
- Saves carry `ifUpdatedAt`; 409 on a newer version.
- A released count frees seats from the highest family order down (ruling 4, owner to confirm).
- Invented names only in tests/fixtures (style בדיוני, דוגמה, ניסיון); the real workbook never enters git.
- Server: `.venv/bin/python -m unittest discover -s server/tests`; client: `npm test`, `npm run typecheck`.

## Review Focus

1. A member asking for another family's seats, the full layout, or another Kehila's data — 403/404.
2. Paste quirks: merged bimah, two names in a cell, trailing spaces, initials with/without ".", blank
   rows/columns, a family whose seats span two blocks.
3. A family with seats both as a registered family and as a holder (linking union, ruling 7).
4. Layout edited for a future Shabbat while the current one is open: current answers untouched.
5. Responses upload with unmatched rows, duplicate answers (latest wins), counts above the family's seats.

### Task 1: paste parser and matcher (client, pure)
`src/seats/paste.ts` (TSV/HTML-table clipboard → grid of cells: seat{family, initial?, order} / empty /
bimah / unassigned; blocks by empty columns; row labels column detected), `src/seats/match.ts` (normalize
Hebrew names: final letters, geresh/gershayim, maqaf, initials with/without "."; suggest matches against
families and holders with a "why"), tests with an invented paste in the real format (+ all quirks above).

### Task 2: server — layouts, holders, assignments
`repo_seating.py`, `routes_seating.py`, `seating_rules.py` (strict validation: grid ≤ 40×60, cell kinds,
block names, seat ids). Routes (gabbai): GET/PUT layout versions with `effectiveFrom` (Friday) and
`ifUpdatedAt`; holders CRUD (name ≤ 60, phone optional, validated like profile phones); PUT assignments
(seatId → `family:<id>` | `holder:<id>` | null) per layout version; history list. Deletion/export hooks.

### Task 3: server — weekly state, member cut, on behalf, responses
Per Shabbat × prayer (ערב שבת / יום שבת; חג/מגילה events later): released seat ids, who updated (member /
gabbai flag). Member: `GET …/seats/me` → only his frame(s) + his seats' states + deadline; `PUT …/seats/me`
(before the deadline). Gabbai: full state, `PUT` on behalf (any time, marked), responses apply
(`{event, rows:[{household, released, requests?}]}` with highest-order-first) + undo per Shabbat; counted
areas' requests stored. Push/reminders not in this plan.

### Task 4: server — link holder to family
Suggestions (new/approved members whose phone or normalized name matches a holder), confirm link (union of
seats, ruling 7), holder deleted after the move; tests incl. two holders for one family.
